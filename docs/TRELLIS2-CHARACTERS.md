# TRELLIS.2 character workflow

This integrates [your TRELLIS.2 fork](https://github.com/yousseffekryk98-droid/TRELLIS.2) with the existing Vite/Three.js game. **It does not contain pre-generated NINJAGO meshes.** Generating them requires a CUDA workstation and character reference images you are allowed to use.

## Generate a fighter

1. On a Linux NVIDIA GPU machine with at least 24 GB VRAM, install the fork according to its README (CUDA dependencies and model weights required).
2. Choose a **full-body isolated** image of the **correct costume/era**. A single image cannot accurately reconstruct every hidden angle. Keep the full minifigure visible, with minimal occlusion and ideally a transparent background.
3. From the TRELLIS.2 fork, run (replace the game checkout directory):

```sh
python tools/export_ninjago_character.py \
  --image /path/to/approved-kai-reference.png \
  --character-id kai-tournament \
  --output-dir /path/to/LEGO-Ninjago-Tournament/public/assets/models/fighters/trellis2 \
  --pipeline-type 512 --faces 45000 --texture-size 1024
```

Use roster IDs from `src/features/characters/roster.ts` (or the expanded catalog). Supported examples: `lloyd-tournament`, `kai-tournament`, `jay-tournament`, `cole-tournament`, `zane-techno`, `nya`, `skylor`, `master-chen`.

4. In the game repository, run:

```sh
npm run sync:trellis
npm run test:trellis
npm run build
```

The generated catalog `src/features/characters/trellis2.generated.ts` points the character selector to real existing GLBs. When a TRELLIS file is present, that character selects it by default; the pre-existing procedural models and variants remain available. If a mesh fails to load, the game displays its existing procedural model.

## Limitations

* TRELLIS.2 is an **offline image-to-3D asset generator**, not an animation engine or a browser/mobile dependency. Running this step on a PC is required before shipping a static game.
* The output is a **single unrigged textured mesh**, so body parts will not perform the game's procedural limb motion. Existing movement, attacks, VFX, weapon nodes and collisions are still controlled by the game. For production-quality moving LEGO characters, **manually separate/rig** the generated parts into the game's `torso`, `head`, `leftArm`, `rightArm`, `leftLeg`, and `rightLeg` contract, then import using the existing authored-character pipeline.
* Automatic normalization fits the model to roughly 3.1 game units in height. Review orientation, head/leg placement and weapon intersections in the preview before release.
* For close fidelity to **Tournament of Elements** outfits, use the correct costume reference and perform manual visual comparison. AI generation alone does not promise exact cartoon geometry or printing.
* Do not claim generated likenesses are official. Use images and derived assets only when you have the required permissions, and record provenance/licensing in `docs/ASSET-SOURCES.md`. A public fan project may still require permission for official character likenesses.
* WebGL compatibility and performance depend on the exported mesh/texture size. Test desktop, Android and low-end mobile devices.
* GLBs placed under `public/assets/models/fighters/trellis2/` are project assets; unlike procedural files generated by prebuild, they must actually be committed/uploaded if they should appear on another device.
